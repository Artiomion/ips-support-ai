# Сквозные тесты: A08

Первый набор A08 проверяет настоящий HTTP API и PostgreSQL через Playwright:
чужая компания и другой клиент того же виджета не читают и не изменяют диалог,
заявки разделены по компаниям, внутренние заметки не попадают к клиенту,
preflight разрешён только origin виджета. MSW не используется.

Браузерный сценарий в Chromium запускается с обычным окном и мобильным
viewport. Сотрудник входит в панель на одном origin, работающую с API на
другом origin, видит только заявки своей компании, отправляет ответ и
внутреннюю заметку. Публичная история содержит ответ, но не заметку.
После перезагрузки страницы сохраняются сессия и изоляция очереди.

Запускайте только на отдельной тестовой базе: каждый запуск создаёт новые
вымышленные компании и не удаляет их. В CI PostgreSQL создаётся заново для
каждой проверки; отдельный seed и доступы участников не нужны.

Из корня репозитория:

```sh
docker compose -f infra/compose.yaml up -d --wait postgres
```

Из `backend/`: `uv sync --frozen`, затем `uv run alembic upgrade head`.
Из корня: `npm ci`, `npx playwright install chromium` и `npm run test:e2e`.
Playwright сам запускает backend на `127.0.0.1:8000` и панель на
`127.0.0.1:5173`; оба порта должны быть свободны. Сервер проверяется через
`/health/ready`. Для локального Linux могут понадобиться зависимости браузера:
`npx playwright install --with-deps chromium`.
При нестандартных настройках задайте `DATABASE_URL` тестовой базы в окружении.
Только HTTP-проверки можно запустить без установки браузера:
`npm run test:e2e -- --project=api`.

Это ещё не полный сквозной M4: клиентский виджет в браузере,
ответ ИИ с источником, claim, confirm и продолжение по email добавляются
по мере готовности B/C. `core.spec.ts` пока не создан. CI не подтверждает
работу настоящего ИИ или внешнего SMTP. Критерии — в `docs/verification.md`.
