# Запросы для экономной работы

## Начать карточку

```text
Выполни карточку <ID> из docs/plans/track-<a|b|c>.md.
Сначала прочитай AGENTS.md, локальную инструкцию и только входы карточки.
Сохрани замороженный контракт; соседние сервисы подмени указанными fake.
Разрешённые изменения — пути карточки. Не подключай агентов автоматически.
Делай по одному проверяемому куску; для бизнес-логики сначала failing test.
Не перерабатывай архитектуру и не реализуй следующие карточки.
В конце: изменённые файлы, фактические команды и результаты, ограничения,
текст PR. Если нужен чужой общий файл, подготовь точное маленькое изменение
для его владельца и продолжай независимую часть.
```

## Передать ограниченный сложный вопрос сильной модели

```text
Карточка: <ID>. Блокер: <один конкретный вопрос>.
Ожидается: <поведение>. Получено: <факт/короткая ошибка>.
Уже проверено: <не более двух подходов и результаты>.
Файлы: <3–5 точных путей>. Контракт: <operationId/порт>.
Нужен диагноз/решение для этого места, без перепланирования проекта.
```

## Продолжить в новой сессии

```text
Продолжи <ID> в ветке <branch>. Прочитай AGENTS.md и карточку.
Готово: <кратко>. Осталось: <один следующий шаг>.
Проверки: <команда — результат>. Не проверено: <что именно>.
Последнее решение/блокер: <одно предложение>.
```

## Проверить PR

```text
Проверь diff PR <URL> по карточке <ID> и её критерию приёмки.
Фокус: поведение, права/tenant, приватность, контракт, гонки и регрессии.
Сообщай только конкретные замечания с воспроизводимым примером и путём.
Не запрашивай косметический рефакторинг и не переписывай PR самостоятельно.
```

Сохранять handoff в описании PR/issue или в персональных заметках,
а не в общем AGENTS.md. Не вставлять туда весь лог сессии.
