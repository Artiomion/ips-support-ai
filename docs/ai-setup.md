# Инструменты ИИ и переносимая настройка

## Минимальный набор

Файлы проекта — обязательный рабочий контекст. Внешние навыки и плагины
помогают, но их отсутствие не должно блокировать код. ИИ каждого участника
сначала читает `AGENTS.md`, затем свою карточку. Не переносить личные пути
автора, его токены, `.codex/config.toml` и весь каталог навыков.

| Инструмент | Статус при подготовке | Роль в проекте | Если недоступен |
|---|---|---|---|
| GitHub plugin | Подключён у автора; чужие аккаунты не проверены | Читать issue/PR и diff | Git + gh CLI |
| Context7 plugin | Подключён у автора, запрос FastAPI выполнен | Актуальная документация, адресный запрос | Официальная документация библиотек |
| playwright skill | Исходник проверен; локальная установка опциональна | Проверки UI в A06/A08 и отладка браузера | Обычный Playwright проекта |
| security-best-practices skill | Исходник проверен; локальная установка опциональна | Точечный secure-default review B02/C06 | Security-инварианты и tests карточки |
| gh-fix-ci skill | Проверен, выключен из набора по умолчанию | Только диагностика упавшего GitHub Actions | gh run view и локальный повтор |
| gh-address-comments skill | Проверен, выключен из набора по умолчанию | Обработка согласованных PR замечаний | Читать PR и применять конкретное поручение |

Два последних навыка требуют уточнения/одобрения на отдельных шагах в своих
инструкциях. Поэтому их не включаем во все сессии. Прямое поручение участника
определяет авторизованный объём; если сам навык реально блокирует действие,
ИИ должен объяснить точное правило и ссылку на него.

Источники: [официальный каталог OpenAI](https://github.com/openai/skills/tree/main/skills/.curated),
[playwright](https://github.com/openai/skills/tree/main/skills/.curated/playwright),
[security-best-practices](https://github.com/openai/skills/tree/main/skills/.curated/security-best-practices).
Здесь playwright — навык автоматизации браузера через CLI; он не заменяет
тестовые спецификации `@playwright/test`, явно предусмотренные A08.

## Что проверено и чего не устанавливаем

Просмотрен доступный в среде каталог: Python/Go, планы, code review, security,
skills installer, GitHub/Context7, документы/таблицы, медиа, hosted sites и
прочие предметные инструменты. Отобран набор по реальным задачам, а не весь
каталог «на всякий случай».

- `modern-python` использован при подготовке подхода uv/Ruff/ty; нужные правила
  уже записаны в backend/AGENTS.md. Отдельная установка для команды не нужна.
- `planning-with-files` использован для этой подготовки. В ходе параллельной
  разработки общий task_plan.md не должен переписываться тремя моделями;
  задачи и PR заменяют этот процесс.
- Superpowers применён при подготовке дизайна/плана. Не обязательная зависимость
  команды: многоэтапные вопросы и автоматические agents расходуют лимиты.
  Не копировать эту установку с личного компьютера и не ставить весь пакет
  автоматически. Если участник уже его использует — прямые инструкции проекта
  и пользователя определяют область работы; одна карточка уже содержит план.
- Go/Goravel skills не соответствуют выбранному Python backend.
- Hugging Face training, fine-tuning, Kaggle и Remotion не нужны для RAG:
  ядро использует поиск и вызов готовой модели, собственного обучения весов нет.
- CodeQL, supply-chain audit и differential/post-patch review — по отдельному
  запросу или перед реальным запуском, не на каждом учебном PR.
- Sites/Higgsfield/Canva/Figma, Google Drive/Slack/Notion и дополнительные
  media/document plugins не нужны для репозитория и ядра. Приложение не
  публикуется через hosted-site генератор; исходный код остаётся в GitHub.
- Context-mode можно использовать, если он уже настроен; установка/hooks
  не является prerequisite и не обещает фиксированную экономию токенов.

## Установка навыков другим ИИ

Из корня клона:

```bash
python3 scripts/bootstrap_ai.py --check
python3 scripts/bootstrap_ai.py --install
```

Скрипт скачивает архив публичного `openai/skills` по **точному commit** из
`.ai/tooling.json`, сверяет blob hash каждого SKILL.md и копирует два выбранных
навыка вместе с references/scripts в `.agents/skills/`. Скачанные scripts
не выполняются. Для повторной установки проверяются хеши файлов; изменённый
или посторонний каталог не перезаписывается. Локальные установки игнорируются Git.
Если отдельная установка Python на macOS не настроила корневые сертификаты,
загрузчик использует системный curl с проверкой TLS; проверка сертификата
никогда не отключается. Без корректного TLS и без curl установка завершится
ошибкой, а локальная разработка останется доступна без этих навыков.

Опциональный навык:

```bash
python3 scripts/bootstrap_ai.py --install --skill gh-fix-ci
```

Offline: заранее скачанный тот же архив передаётся через `--archive <path>`.
Для проверки в безопасной временной папке есть `--dest <path>`.
Обновлять pin осознанным PR после повторного чтения навыков; не менять на main.

В Codex проектные `.agents/skills` предназначены для discovery навыков;
если клиент не обновил список, следующий запрос либо явное чтение SKILL.md
позволяет продолжить. В Claude Code `CLAUDE.md` направляет к AGENTS и этим
файлам; это **не обещание автоматической регистрации** Codex-навыков как
нативных Claude plugins. Пути из текста навыка вроде `$CODEX_HOME/skills/...`
нужно адаптировать к фактической локальной установке. Никакие глобальные
инструкции/настройки скрипт не изменяет.

## Подключение плагинов

1. ИИ проверяет, доступны ли GitHub и Context7 в его клиенте. При наличии
   не создаёт второе подключение того же сервиса.
2. В Codex Desktop найдите GitHub и Context7 в доступных плагинах, установите
   и подключите личные аккаунты. OAuth, выдача прав и trust выполняются
   владельцем аккаунта; ИИ не может установить и подтвердить это за другого.
   В manifest записаны реально найденные ID, но интерфейсы каталога могут меняться.
3. Fallback для GitHub: установленный gh, `gh auth login`, затем
   `gh auth status`. Никогда не просить прислать token в чат или Git.
4. Context7: использовать соответствующую инструкцию для своего клиента:
   [Codex](https://github.com/upstash/context7/blob/master/docs/clients/codex.mdx),
   [Claude Code](https://github.com/upstash/context7/blob/master/docs/clients/claude-code.mdx).
   Официальный setup использует `npx ctx7 setup --codex` либо `--claude`;
   это альтернативный способ, если встроенный plugin не подключён.
   Он меняет пользовательскую конфигурацию и требует OAuth. Перед запуском
   проверить текущую официальную инструкцию, не выполнять вслепую в bootstrap.
5. Проверить чтением одного issue/PR (после создания) и одним точным запросом
   документации. Не передавать в Context7 исходные переписки, ключи и ПД.

Плагины разработчика не входят в runtime платформы. ИИ-консультант продукта
работает через собственный provider adapter, не через личный плагин автора.

## Экономия моделей и контекста

По умолчанию: Terra medium либо доступная кодовая модель сопоставимого класса;
Opus low — допустимый выбор участника, если ему подходит в его клиенте.
Это организационная рекомендация, а не гарантия стоимости/качества и не
глобальная настройка аккаунта.

Одна карточка, одна сессия, связанные файлы, targeted tests. Не читать всё ТЗ
каждый раз, не запускать несколько reviewer agents на обычный PR, не прикладывать
полные логи. При двух неудачных разумных попытках передать конкретный вопрос
по шаблону в docs/prompts/task.md. Сильная модель нужна для изменения архитектуры,
auth/tenant-границ, сложной гонки и финальной проверки безопасности; обычные
экраны, CRUD и адаптеры выполняются по текущему плану.
