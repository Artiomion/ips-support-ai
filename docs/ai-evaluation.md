# C08: проверка ответов и безопасной передачи

## Автоматическая проверка

`backend/tests/fixtures/ai-cases.json` содержит 12 фиксированных сценариев и
синтетические статьи двух организаций. Тест создаёт отдельные организации,
виджеты, разделы и диалоги в тестовой PostgreSQL, проверяет клиентский поиск и
обработчик C05/C06 и удаляет только созданные им данные. Не запускайте тесты
на рабочей базе. Нужна база с применёнными миграциями, включая `widget_sections`.

Из каталога `backend`:

```text
python -m pytest tests/ai/test_eval_cases.py -q
```

Провайдер в этих тестах детерминированный и работает без сети. Ошибку,
истечение времени и запрет квоты тест создаёт через контролируемые адаптеры;
они не проверяют фактические лимиты B06 или реальный сетевой timeout. Результат
оценивают обычные assertions, а не другая языковая модель.

| Сценарий | Что проверяется |
| --- | --- |
| known | Публичная статья своей организации даёт ответ с её ID и ревизией. |
| unknown | При отсутствии источников открывается передача специалисту. |
| ambiguity | Общий вопрос без подходящего источника передаётся специалисту. |
| human request | Явный запрос клиента создаёт заявку и отменяет ожидающий ответ ИИ. |
| failed answer | Некорректный ответ не сохраняется; ручная передача доступна. |
| urgency | Срочный вопрос без источника передаётся специалисту. |
| injection | Инструкция показать секреты и вызвать URL не запускает инструмент и не раскрывает чужие данные в этом сценарии. |
| private | Внутренняя статья Alpha не попадает в клиентский ответ. |
| cross-tenant | Клиент Alpha не получает статью Beta; поиск самой Beta её находит. |
| timeout | Имитированный timeout не мешает ручной передаче. |
| quota | Имитированный отказ квоты не мешает ручной передаче. |
| race | Если человек подключился во время генерации, ответ ИИ не сохраняется. |

В сценарии ambiguity проверяется вопрос без подходящего источника, а не
разрешение противоречий между несколькими статьями. Заглушка не классифицирует
срочность: сценарий urgency проверяет передачу человеку, а не выставление
приоритета `urgent`. Проверка prompt injection охватывает заданный пример и
не доказывает защиту от всех атак. Сценарий human request использует явное
действие передачи; распознавание свободной просьбы моделью не оценивается.

## Проверка настоящего провайдера перед M4

Пока используется заглушка: **живой smoke не выполнен, M4 этим PR не принят**.
После отдельного согласования выбранного провайдера и расходов используйте
только синтетическую базу и тестовый стенд B08. Понадобится отдельно настроить
секреты в окружении стенда; не записывайте их в репозиторий или отчёт.
Настоящий провайдер и SMTP проверяются по `docs/demo-live-services.md`.

Проверьте 3–5 вопросов, например: про возврат Alpha, неизвестный вопрос,
неоднозначный вопрос, запрос на специалиста и запрос об информации Beta из
виджета Alpha. Для каждого зафиксируйте ожидаемый и полученный результат,
ID и ревизии цитат, факт передачи человеку и обнаруженные ограничения. Не
используйте персональные данные, реальные диалоги или настоящие секреты.

Шаблон отчёта:

```text
Дата и часовой пояс:
Провайдер и модель:
Версия стенда / commit:
Для каждого вопроса: вопрос; ожидание; результат; источники и ревизии;
                     передача человеку; пройдено/не пройдено; замечания.
Ограничения, ошибки, итог и автор проверки:
```

Наличие ошибок приватности, неверных цитат, недоступности ручной передачи,
отсутствие отчёта либо отсутствие проверки настоящих AI/SMTP-сервисов означает,
что совместный M4 gate остаётся открытым. Не подменяйте отчёт результатами
заглушки и не записывайте ключи, токены, адреса или содержимое писем.
