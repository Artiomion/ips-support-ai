# Первый запуск участника

1. Роли записаны в `docs/team.json`: A — bachaa7, B — Artiomion,
   C — Gwynblai. Изменение ролей согласуйте до первых PR и обновите CODEOWNERS.
2. Приглашения коллегам отправлены. Примите приглашение GitHub, чтобы получить
   доступ к приватному репозиторию. Каждый работает со своим аккаунтом и токеном.
3. Клонируйте репозиторий. Прочитайте `AGENTS.md`, свою дорожку и
   `docs/ai-setup.md`. Остальные документы читайте по ссылкам своей карточки.
4. Запустите `python3 scripts/bootstrap_ai.py --check`.
   При необходимости попросите своего ИИ выполнить `--install`.
5. Для старта A берёт A01, B — B01, C — C01. У них нет блокирующих зависимостей.
   C01 использует самостоятельные DTO/тестовые контексты и не ждёт auth B02.
6. Копируйте шаблон из `docs/prompts/task.md`; добавьте ID карточки.
   Не просите модель «сделать весь проект» или «реализовать всю дорожку».
   `python3 scripts/task_context.py B04 --contracts` выводит карточку и только
   принадлежащий ей API-контракт. A читает операции своих потребителей по
   operationId, а не весь большой OpenAPI-файл в каждой сессии.
7. Первые три PR объединяются как M0. После этого каждый начинает следующую
   карточку на моках или портах, даже если соседний API ещё не готов.

## Что уже существует

Инструкции, OpenAPI-проект, примеры, карточки, шаблоны GitHub, проверка
подготовленных файлов и установщик навыков. Каталоги продукта содержат
инструкции и описания будущих путей, а не работающий сервер/клиент.

## Что создадут первые карточки

- A01: npm workspace, web/widget skeleton, test/build scripts.
- B01: uv backend, FastAPI app factory, PostgreSQL Compose, Alembic,
  backend CI, порты и composition root.
- C01: доменные DTO и тестовые адаптеры conversations/AI/knowledge;
  до B01 — чистые unit tests с временным окружением uv и только согласованными
  зависимостями. После B01 переносит их в общий backend без второго lock-файла.

Сквозной результат M4: две компании → встроенный виджет → ответ с источником
→ передача человеку → ответ специалиста → подтверждение решения.
Проверки и сценарий защиты — `docs/verification.md`.
